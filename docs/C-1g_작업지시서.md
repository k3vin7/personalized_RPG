# C-1g 작업 지시서 — 공격 각·궤적·카메라 줌

작성 2026-11-04. C-1(검·방패·맨손 뼈대) + f-2(KayKit 임시 모델) 완료 상태에서 시작한다.

## 목적
공격이 더 시원하게 보이고 맞게 한다. 판정만 넓히는 게 아니라 **판정·애니·궤적·범위 표시가 같은 각 값을 쓰게** 묶는다. 그리고 로아식 스크롤 줌을 넣는다.

## 건드리지 않는 것
- 입력 방식(우클릭 이동·키 선택·좌클릭 시전·스마트키 기본 꺼짐) — 그대로
- 선딜·후딜 값, 체인, 런지, 캔슬 — 없음. 이 지시서는 조작을 바꾸지 않는다
- 기술 종류·피해 계수·스태미나 — 그대로

## 공통 규칙
- 아래 숫자는 전부 **기본값**이다. 전부 디버그 패널 슬라이더로 노출하고 런타임에 바꿀 수 있어야 한다
- 각 값의 **단일 소스**는 기술 데이터(검 기술 행)다. 판정·애니·궤적·범위 표시·예고 장판이 전부 이 값을 참조한다. 코드에 각도 숫자를 따로 박지 않는다
- 소단계(a~e) 하나 끝낼 때마다 **검사 → 보고 → 정지**. 다음 소단계는 내 승인 뒤 시작

## a. 판정 — 쓸고 가는 판정
- 순간 부채꼴 판정을 버리고, **휘두르는 동안 날이 지나간 구간을 쌓아 가며 판정**한다 (매 프레임 현재 날 각도 구간을 누적). 적은 날이 그 위치를 지나는 순간 맞는다
- 한 번의 휘두름에 같은 대상은 1회만 명중
- 기본값:
  - 횡베기: 수평 호 **240°** (정면 기준 좌우 120°), 높이는 기존 "낮게" 그대로
  - 종베기: 수직 호 **120°** — 머리 위(수직)에서 시작해 앞으로 내려오는 평면, **수평 폭은 기존 값 그대로** (넓히지 않는다)
  - 찌르기·흘리기: 변경 없음
- 규칙: **판정 각 ≥ 애니가 실제로 그리는 각 − 여유(기본 20°)**. 판정이 애니보다 넓어도 되는 건 여유값까지만
- 검사: 허수아비 3개를 정면·좌 110°·우 110°에 세우고 횡베기 1회에 셋 다 맞는지. 뒤쪽(좌우 130°)에 세운 건 안 맞는지. 종베기는 머리 위 허수아비(점프 높이)와 정면 허수아비가 맞고, 좌우 45°는 안 맞는지

## b. 애니·궤적
- KayKit 휘두르기가 240°를 못 그리면 **상체 회전 + 휘두르는 동안 루트(몸) 회전**으로 궤적을 채운다. 애니 클립을 늘리는 게 아니라 회전을 얹는다
- 막대 메시 **궤적 잔상(트레일)**이 a의 각 값을 참조해 같은 호를 그린다. 종베기 트레일은 수직 평면
- 애니가 실제로 그리는 각을 측정해 보고한다 (횡·종 각각). a의 여유 규칙이 지켜지는지 여기서 확인
- 검사: 슬라이더로 횡베기 각을 180 → 240 → 300으로 바꿀 때 트레일과 몸 회전이 따라 변하는지. 숫자 박힌 데가 있으면 안 따라오니까 그게 검사다

## c. 범위 표시
- 스마트키 꺼짐 상태의 부채꼴 표시가 a의 값을 참조한다. 횡베기는 수평 부채꼴 240°, 종베기는 수평 폭 그대로에 사거리만
- 검사: 슬라이더 바꾸면 표시도 즉시 바뀌는지

## d. 몬스터용 각 분리 (C-2 대비)
- 기술 데이터에 **플레이어 각 / 몬스터 각** 필드를 따로 둔다. C-2의 산적 검병이 플레이어 공격 코드를 재사용할 때 몬스터 각을 쓰게
- 기본값: 몬스터 횡베기 **180°** (플레이어보다 좁게. 옆으로 빠져 피하는 게 가능해야 하니까). 슬라이더
- 예고 장판(C-2에서 만듦)도 이 몬스터 각을 참조하게 자리만 잡아둔다. 지금 장판을 만들진 않는다

## e. 카메라 줌
- 마우스 스크롤 = 거리 + 각 **동시 보간**. 멀면 위에서(기존 각), 가까우면 눕는다
- 기본값: 거리 최소 / 최대 = 기존 거리의 0.5배 / 1.0배. 각 = 최대 거리에서 기존 각, 최소 거리에서 **35°** (지면 기준). 각 하한 35°는 슬라이더
- **회전은 넣지 않는다** (11-02 결정). 줌만
- 건물 진입용 "카메라 축소" 코드가 있으면 그걸 확장한다. 새로 짜지 않는다
- 마우스 조준(화면 → 바닥 평면 투영)은 **어느 줌 단계에서도 정확**해야 한다. 각이 누울수록 틀어지면 보고
- 검사: 최대 확대·최소 각에서 ① 맵 끝·하늘·블록아웃 바깥이 보이는지 ② 지붕 숨김·벽 투명 처리가 여전히 맞는지 ③ 허수아비에 마우스 올리고 횡베기 쳤을 때 조준 방향이 맞는지. 셋 다 스크린샷

## 보고 형식 (소단계마다)
1. 바꾼 파일·함수 목록 (한 줄씩)
2. 슬라이더 목록과 기본값
3. 검사 결과 — 통과/실패와 스크린샷 (b·e는 짧은 영상이면 더 좋음)
4. 숫자가 아직 코드에 박혀 있는 곳이 있으면 전부 적는다
5. 정지. 다음 소단계는 승인 뒤
