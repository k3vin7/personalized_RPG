## N·M 단계 요약

각 단계가 무엇을 만들었고 어떤 규칙을 세웠는지. 커밋 본문에서 뽑았다. 수치는 그 커밋 시점의 실측이다.

### N-1 튜닝 값 서버 소유 (9fd6476)
- 만든 것: `PhysicsTuning`(60개)은 서버 표. 클라 복제본은 서버 푸시(`push_server_tuning`)의 import만 쓸 수 있고, `Intent.SERVER_TUNING`이 필드·타입 검사 → 기본값 기준 클램프 → 서버 사본 → 전 피어 푸시. `LocalTuning` 7개(스마트키·조준·입력 타임아웃·잡기 커서 반경·던지기 임계·충전 최대)만 `Tuning.values`.
- 규칙: 판정·궤적·비용에 들어가는 값은 전부 `Tuning.server`. 클라 쪽 setter는 쓰기를 거부한다(테스트에서 클라에 써도 아무 일 없음이 의도).
- 검사: n_checks 19건(표 분리, 클라 쓰기 거부, 위조 push 거부, 클램프, 요청→표→복제). 2인 0ms N 19/0, C 99/0.

### N-2 이동 검사 경고 → 보정, Intent.DASH 통지 (3fc4d21)
- 만든 것: `_check_move`가 피어별 마지막 수용 위치를 기록하고, 허용치 초과가 2표본 연속이면 `correct_position`으로 소유자를 수용 위치에 스냅(속도 0, 이동·돌진 취소, TELEPORT_BLIND). `Intent.DASH`는 승인 없는 통지로, 돌진 속도(20.6 m/s)는 통지 뒤 돌진 시간+슬랙 창 안에서만 허용.
- 규칙: 평시 수평 상한은 max(이동속도, 도약 상한)×tolerance = 12.9 m/s. 사망·잡힘·등반·용서 표본·힘 기억 안은 현재 위치를 수용하고 카운트 0. 쿨다운 안 돌진 통지도 초과 표본.
- 검사: N 27/0(0·200ms), 클라 3배 달리기 → 보정 수신·거리 절단, 정상 플레이 보정 0건. C/D/E/F/G/B-e에 `no_corrections` 검사.

### N-3 잡힌 사람의 위치를 서버가 손에 둠 (04bb04b)
- 만든 것: `_place_held_people`가 보유 표의 사람을 매 스텝 서버 화면의 `holder.hand_position()`에 두고 `push_held_position`(0.05 s)으로 전 피어에 보낸다(돌·허수아비와 같은 방식). 놓기는 서버 `_release_person` → `release_at`(reliable, 보유 표 변경보다 먼저).
- 규칙: 잡힌 동안 소유자는 자기 위치를 쓰지 않는다. 잡힌 몸과 보유자는 충돌 예외(없으면 손 위치 캡슐이 보유자 머리와 겹쳐 20 m 밀려났다).
- 검사: 호스트가 클라를, 클라가 호스트를 들고 선 채 손 거리 양쪽 화면 0.000 m(0·200ms), 걸을 때 0.339 m(기록만), 놓은 뒤 위치 차 0.000 m. E 111/0.

### N-4 리스폰 위치 서버 선택 + B-a 클라 3건 원인 수정 (f9f0047)
- 만든 것: `server_respawn`이 서버 화면 기준 빈 마크를 골라 `apply_respawn(at)`으로 보낸다. 살아 있는 몸의 R도 서버 응답을 기다린다. 돌 스폰 y = 반지름+0.05, 내려놓기(DROP)는 보유자 옆 바닥 빈 자리(`_put_down_rock`), 리스폰 순간이동에 TELEPORT_BLIND.
- 규칙: 클라 리스폰은 비동기(요청 → 서버 응답). 몸을 순간이동시키는 모든 곳은 `collision_layer = 0`을 BLIND 동안(머리 위 돌이 220 m/s로 날아간 원인). 하네스는 `respawns_applied`가 늘어난 뒤 배치.
- 검사: B-a 31/0+20/0, B-b 27/0, B-c 49/0, B-d 35/0, G 20/0, E 111/0, N 50/0.

### N-5 돌 피격 source, 발사각 함수 통합, 동기화 상수 통합 + N_throw_cliff (0f86e86)
- 만든 것: 돌 피격 `source_peer` = 던진 사람(THROWER_GRACE 안, 아니면 0). `Ballistics.cheapest_launch`가 점프 계획과 `_arc_to`의 공통 식. `SyncRules`(TELEPORT_STEP 2.0 / TELEPORT_BLIND 0.2 / LERP_RATE 18 / YAW 20 / STATE_INTERVAL 0.05) 한 곳. 던져지는 사람은 보유자 뒤가 아니라 날아갈 쪽에 놓는다. 리스폰 뒤 RESPAWN_KILL_GRACE 1.0 s(원격만).
- 규칙: 파일 간에 맞아야 하는 숫자는 한 곳에 둔다. 힘 기억(FORCE_MEMORY)은 공중에 있는 동안 소모하지 않는다.
- 검사: N_throw_cliff(호스트가 클라를 들고 절벽 밖으로 던짐 → 낙사 → 리스폰, 양쪽 0.000 m). N 60/0, G 22/0, B-d 35/0, D 55/0.

### M-1 기술 슬롯 구조 (2e721cd)
- 만든 것: `SkillDef` 리소스(`data/skills/*.tres`: id, 요구 손, 선딜, 후딜, 쿨타임, 사거리, 폭, 피해, power, 결과, tuning_prefix, 표시 훅). 8칸 슬롯(Q W E R A S D F, 디버그 패널로 재배치). 시전 흐름 키 → (스마트키 꺼짐이면 링+좌클릭) → CASTING(선딜) → 의도 → RECOVERING(후딜) → IDLE. 서버 `Intent.SKILL`은 후딜·쿨타임 안 재시전을 서버 시계로 거부, `_rule_strike`는 밀치기와 같은 직사각형 판정. 상태 CASTING/RECOVERING/DOWNED 추가. 키 충돌로 dash F→C, restart R→Home.
- 규칙: 기술 수치는 리소스 @export 또는 `Tuning.server.<prefix>_*` 슬라이더, 코드 리터럴 없음. 선딜·후딜 중 이동·점프·돌진·다른 시전 무시. 밀치기·잡기도 선딜 0으로 같은 흐름.
- 검사: m_checks 36/0(슬롯 채움 규칙, 재배치 후 시전, 후딜·쿨타임 거부, 스마트키 on/off, 클라 시전 서버 판정). C 100/0, B-c 49/0, E 111/0.

### M-2 주먹·발차기·넘어짐 (052c13d)
- 만든 것: 판정 높이 밴드(몸 중심 기준 주먹 +0.3 / 발차기 −0.4, 반높이+0.9). 발차기 결과 = 넘어짐: DOWNED로 down_time 1.0 눕고 getup_time 0.3 기상, 입력 불가, 밀림은 그대로, 다시 맞으면 리셋. 발차기는 돌도 밀고 들린 돌은 제외. 넘어진 보유자는 든 것을 놓친다.
- 규칙: 넘어짐은 지상(또는 이미 넘어진) 대상에만, 공중은 넉백만. 미끄러짐 반환보다 앞에 둔다(발차기 5 m/s < 허용치 7.2라 항상 slid).
- 검사: 주먹 피해 2·후딜, 발차기 → DOWNED 1.30 s → IDLE, 리셋 2.65 s, 돌 3.8 m 밀림, 상태 순서 양쪽 동일. M 57/0(0·200ms), D 55/0, E 111/0.

### M-3 종족 선택대 + 무기 선택대 서버 승인 (0e3898d)
- 만든 것: `RacePedestal` 4개(인간·엘프·드워프·오크), 서서 잡기 키 → `Intent.RACE` → 서버 `_rule_race`(빈손·지상·안 잡힘·등반 아님·안 넘어짐). `Intent.WEAPON`: `set_weapon()`은 요청, 서버가 기록·전달.
- 규칙: 종족·무기는 서버가 소유. 클라가 자기 종족·무기를 직접 쓰면 무효. 서버 표와 소유자 표시가 다르면 카운트.
- 검사: 4종족 받침대 실측(근력·무게·HP·스태미나 = 종족 데이터), 빈손 아닐 때 거부, 미지 종족 거부, 클라 위조 무기 서버 표 불변. M 85/0, E 111/0, D 55/0.

### M-4 캡슐 가변 (a144295)
- 만든 것: `Player.body_scale()` = 종족 키 / 180. `half_height()`·`radius()`가 인간 기준 상수에 비율을 곱하고, 종족이 바뀔 때 모든 피어가 충돌 캡슐·메시·그림자·라벨·나브 에이전트를 다시 맞춘다. 손 높이·판정 밴드·등반 거리·잡기 사거리·사람 놓기 간격이 전부 이걸 읽는다. 나브메시는 1.8 m 하나 유지.
- 규칙: 밀치기 높이 밴드(반높이+0.9)는 지상 대상에만. 공중의 아군은 협동 발사라 제외(넣으면 D의 늦은 밀기가 빗나간다).
- 검사: 인간 1.80/0.40, 엘프 1.70/0.38, 드워프 1.50/0.33, 오크 2.20/0.49(손 높이 1.70/1.61/1.42/2.08). 오크가 인간 머리 위에 2.000 m로 섬. M 91/0, D 55/0, E 111/0(0·200ms), F 35/0.

## 4. 물리 규칙과 공식 (개정본, 이게 기준)

**"이거 되나?" 해보면 진짜 된다. 동작 전용 예외는 두지 않는다.**

### 기본 공식
```
total_weight     = body_weight + gear_weight + held_weight
ratio            = strength / max(total_weight, 0.1)
ratio_mult(r, k) = clamp(1 + k * ln(r / ratio_ref), ratio_mult_min, ratio_mult_max)
ratio_ref        = 0.75          # 인간 수련 0 맨몸 = 1.0배 (기본값)
```
- 점프·돌진·이동·밀기·던지기의 `_base` 값은 전부 **"배율 1.0일 때 = 인간 수련 0 맨몸일 때"** 값이 된다.
- 지금 코드의 `_base` 값은 그대로 두고 기준만 바꾼다. 손맛이 크게 바뀌면 **값을 임의로 조정하지 말고** 전후 실측을 보고한다.

### 밀림 (버티는 힘 삭제)
```
power = base_power × ratio_mult(source_strength / target_total_weight, k_push)
dv    = direction × power                     # brace 항 없음
```
- 미는 쪽 근력은 그대로 들어간다. **맞는 쪽 근력은 거리에 들어가지 않는다** (맞는 쪽은 무게로만 덜 밀린다).
- `k_brace`, brace 계산, 관련 슬라이더·디버그 표시를 지운다.

### 넉백 허용치 (새로 추가)
```
tolerance = target_strength × tolerance_per_strength × race_tolerance_mult
h_speed   = |dv의 수평 성분|
```
지상에 있는 대상에게만 적용한다 (공중·등반 중 대상은 v3 규칙 그대로: 공중은 더하고, 등반 중은 벽에서 떨어진다).

| 조건 | 결과 |
| --- | --- |
| `h_speed ≤ tolerance` | **미끄러짐.** 지상에 남는다. dv의 위쪽 성분은 버리고 수평만 적용 (기존 `force_slide_time/friction` 사용). 든 것은 놓지 않는다 |
| `h_speed > tolerance` | **튕겨나감.** dv를 그대로 적용하고, 위쪽 성분이 `launch_min_up_speed`보다 작으면 그 값으로 올려 공중 상태로 만든다. 공중이 되었으므로 **든 것을 놓는다** (v3 단계 E 규칙: 밀림으로 뜬 경우) |

- 밀치기·피격·충돌·던진 돌·반동 **전부** 같은 힘 이벤트 함수에서 이 비교를 거친다. 동작 전용 예외 없음.
- 허용치 비교는 **서버**가 하고, 결과(미끄러짐/튕겨나감)를 힘 이벤트에 담아 보낸다. 소유 클라는 받은 결과대로만 적용한다.
- 막기(자세 완성도, 막을 때 스태미나 소모)는 **이번 범위 밖.** 함수에 "막는 중이면 여기서 보정" 자리만 주석으로 남긴다.

### 도약 한계 (v3와 같음)
```
v_cap = sqrt(v_jump_max² + v_move_max²)      # 둘 다 근력 배율 적용 값
내 입력으로 낸 발사 속도 |v_self| ≤ v_cap
```
남이 준 힘은 이 상한과 무관하게 더해진다.

### 들기 한계
```
max_lift = strength × lift_per_strength      # 기본 1.2 → 인간 72kg
한손 잡기 = max_lift / grab_one_hand_strength_mult (2.0)
대상 무게(장비 포함) > 한계 → 못 든다
```
사람이든 돌이든 같은 공식. 사람 전용 보정 금지.

### 지구력 → HP·스태미나
```
hp_max      = endurance × hp_per_endurance
stamina_max = stamina_base + endurance × stamina_per_endurance
```
- 지구력 차이가 **HP엔 크게, 스태미나엔 작게** 반영되게 하는 구조다.
- 기본값은 **인간(지구력 70)일 때 지금 코드의 HP 최대치·스태미나 최대치와 같아지게** 정한다:
  - `hp_per_endurance = 현재 HP 최대 / 70`
  - `stamina_base = 현재 스태미나 최대 × 60/88`, `stamina_per_endurance = 현재 스태미나 최대 × 0.4/88`
  - (이 비율이면 엘프 70 = 인간과 같음, 드워프 100 ≈ 인간의 1.14배)
- 스태미나 소모처(돌진·등반·들고 있기·던지기 충전·탈출 연타)와 비용은 v3 그대로.
