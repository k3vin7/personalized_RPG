# 협동 액션 RPG — 프로토타입 개발 순서

기준: `협동_액션_RPG_기획서_v0.3.md` 및 프로토타입 범위 합의
작성일: 2026-10-21
구현 모델: GPT-5.6 sol / medium

## 1. 이번 프로토타입의 목표

**두 사람이 검·방패로 싸우고, 서로 밀어 절벽을 넘는 약 10분짜리 전투·탐험 실험실**을 만든다.

검증할 질문:

1. 우클릭 이동, 점프, 돌진, QWER를 함께 쓰는 조작이 재미있는가?
2. 높이와 외부 힘을 전투·탐험에서 의도적으로 활용할 수 있는가?
3. 온라인에서도 명중·방어·협동 도약을 납득할 수 있는가?

첫 테스트는 이 완성형 전체가 아니라 **1단계의 2인 이동 테스트**다. 이후 단계는 앞 단계의 플레이 테스트를 통과한 뒤 진행한다. 구현 중 발견한 결함은 현재 단계 안에서 해결하고, 다음 단계의 기능을 미리 만들지 않는다.

## 2. 전체 진행 순서

| 단계 | 구현 범위 | 직접 해볼 테스트 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- | --- |
| 1. 이동·접속 실험실 | Godot 프로젝트, 회색 박스 맵, 고정 쿼터뷰, 우클릭 이동, 점프 3종, F 돌진, 가림 처리, 2인 접속·이동 동기화 | 두 창 또는 두 기기로 같은 맵에서 이동·점프·돌진 | 자기 캐릭터만 조작되고, 낙하·벽 충돌·재시작까지 반복 가능 |
| 2. 검·방패 전투 | 고정 QWER, 3D 공격 판정, 체력, 방어·완벽 방어, 검기, 돌진 연계, 허수아비와 근접 적 1종 | 두 사람이 같은 적을 공격하고 방어 | 중복 피해·중복 사망이 없고, 원격 공격과 방어 결과가 설명 가능 |
| 3. 협동 이동·게이트 | 공중 아군 방패밀기, 지상 아군 피해·경직, 근력·무게 프리셋, 절벽 지름길, 레버·다리 | 한 명을 밀어 건너보내고 다리를 열어 둘 다 합류 | 협동 도약을 의도적으로 반복 성공하고, 실패 원인을 이해 가능 |
| 4. 10분짜리 루프 | 훈련 → 전투 → 절벽 → 마지막 전투, 체크포인트, 재도전, 최소 안내 | 처음 하는 두 사람이 시작부터 끝까지 진행 | 개발자 개입 없이 완주·재시작, 실제 두 기기에서 주요 동작 확인 |
| 5. 빌드 차이 검증 | 스태프 추가, 전투 밖 무기 교체, 장착 무기 기반 스킬 풀·QWER 배치 | 검·방패와 스태프가 함께 같은 구간 공략 | 다른 무기를 선택할 이유와 서로 돕는 상황이 실제 플레이에서 발생 |
| 6. 성장·탐험 검증 | 짧은 숙련도 성장, 성장 전후 게이트, 제한된 등반, 로컬 테스트 저장 | 처음 못 가던 곳을 성장 후 재방문 | 숫자 상승이 조작·탐험 변화로 느껴짐 |
| 7. 비공개 테스트 준비 | 4인, 배포·접속 편의, 서버 캐릭터 저장, 최소 콘텐츠 확장 | 외부 테스터의 반복 플레이 | 접속·복구·저장 안정성과 반복 플레이 가치 확인 |

**1~4단계가 이번 프로토타입 범위다. 5단계 이후는 테스트 결과에 따라 진행 여부와 범위를 다시 결정한다.**

7단계는 곧바로 영구 공용 세계 알파 출시를 뜻하지 않는다. 공용 세계, 전용 서버 운영, 계정·보상 검증은 별도 설계가 필요하다.

## 3. 단계별 구현 순서

### 1단계 — 첫 2인 이동 테스트

1. 현재 파일과 설치된 Godot 버전을 확인한다.
2. 실행 가능한 프로젝트와 간단한 테스트 맵을 만든다.
3. 호스트·참가와 플레이어 생성·제거를 붙인다.
4. 로컬 캐릭터의 우클릭 이동과 고정 쿼터뷰를 구현한다.
5. 점프·돌진·낙하 복귀를 구현하고, 각 동작을 두 클라이언트에서 확인한다.
6. 가장자리 이동 의도, 도달 불가 클릭, 가림 처리와 높이 표시를 다듬는다.
7. 첫 플레이 테스트 안내와 실제 검증 결과를 남긴다.

상세 실행 지시는 `FIRST_PLAYTEST_PROMPT.md`를 사용한다.

### 2단계 — 검·방패 전투

1. 스킬 정의와 시전·명중·피해 적용 경계를 분리한다. 장착 UI는 만들지 않는다.
2. 허수아비에 Q 찌르기와 W 횡베기부터 적용한다.
3. 근접 적 1종에 추적·공격 예고·공격·회복 상태를 구현한다.
4. E 방어·완벽 방어·실패와 적 대상 방패밀기를 구현한다.
5. R 검기를 추가한다. 충전량에 따른 피해·사거리만 다룬다.
6. F와 기술을 함께 사용할 수 있게 하고, 지상·공중 사용 제한을 적용한다.
7. 2인 공격과 방어를 검증한다. 명중 보고 중복 제거, 호스트의 적 HP·사망 확정을 확인한다.

임시 규칙: 검기는 지상에서 느리게 이동하며 충전 가능, 공중 시전 불가. 검기끼리 충돌과 숙련도별 변형은 제외한다. 이동·공격·방어 권한은 기획서 원칙을 따르되, 공격 이벤트 ID와 방어 결과를 합쳐 최종 피해를 한 번만 적용하는 흐름을 먼저 정한다.

### 3단계 — 협동 도약

1. 방패밀기의 힘 이벤트를 적·아군에 공통으로 전달한다.
2. 공중 아군은 피해 없이 궤도가 바뀌고, 지상 아군은 피해·경직을 받게 한다.
3. 근력·무게 프리셋과 속도·점프·밀기 힘의 상한을 설정한다.
4. 혼자 갈 수 있는 우회로와 협동으로 단축되는 절벽 경로를 만든다.
5. 건너간 사람이 레버로 다리를 열어 남은 사람을 합류시킨다.
6. 두 기기에서 도약을 반복하며 지연·판정 범위·성공 피드백을 조정한다.

임시 규칙: 낙사는 체크포인트 복귀로 처리하며 영구 페널티는 없다. 아군 피해·경직·낙사 관련 옵션은 데이터로 조정한다.

### 4단계 — 첫 완주 테스트

1. 따로 검증한 기능을 하나의 짧은 동선으로 묶는다.
2. 조작 안내, 체크포인트, 마지막 전투 완료 표시와 재시작을 추가한다.
3. 두 사람이 상대를 기다리거나 재합류할 수 있는지 확인한다.
4. 낙사, 한 명 이탈, 반복 재시작에서 진행이 막히지 않는지 확인한다.
5. 실제 플레이에서 어려웠던 조작과 재미있었던 협동 행동을 기록한다.

완주 시간은 약 10분을 목표로 조절한다. 플레이 시간을 채우기 위한 반복 전투는 추가하지 않는다.

## 4. 이번에 제외하는 기능

- 검·방패 외 무기, 자유 장착, 스킬 편집 UI, 전투 중 무기 교체
- 벽 등반·벽점프·블링크·마법 발판
- 숙련도 경험치, 장기 능력치 성장, 종족, 임계점 특전
- 아이템 드랍, 인벤토리, 상점, 제작·강화
- 스토리·퀘스트·히든 콘텐츠·도시 이동·정식 보스
- 계정, 상용 백엔드, 서버 캐릭터 저장, Steam 연동, 4인 지원
- 최종 아트·애니메이션·음향 제작

콘텐츠와 저장을 아직 만들지 않는다는 뜻이며, 정식 게임의 서버 저장 방침을 바꾸는 것은 아니다. 프로토타입의 로컬 저장은 원 기획서 11장의 예외 범위에서만 사용한다.

## 5. 테스트 결과에 따른 판단

- 이동 자체가 불편하면: 무기 추가 전에 클릭 판정·카메라·점프를 수정한다.
- 로컬은 괜찮고 원격에서 불편하면: 콘텐츠 추가 전에 전송·보간·이벤트 처리를 수정한다.
- 협동 도약이 우연에 가깝다면: 판정 범위와 피드백을 개선하고, 그래도 안 되면 동작 설계를 다시 검토한다.
- 검·방패 조작은 좋지만 협동할 이유가 없다면: 5단계에서 상호 보완적인 스태프 역할을 우선 검증한다.
- 1~4단계가 안정적이면: 빌드 다양성 → 성장·탐험 순서로 넓힌다.

## 6. 구현 모델에 작업을 맡기는 단위

한 번의 요청에는 한 단계의 목표와 완료 기준을 준다. 구현 중에는 실행 오류 수정과 현재 단계 검증까지 마무리하게 하되, 다음 단계로 자동 확장하지 않게 한다.

첫 요청은 `FIRST_PLAYTEST_PROMPT.md` 전체를 전달한다. 이후 요청에는 해당 단계 범위, 직전 테스트에서 발견한 문제, 실행·테스트 방법을 함께 전달한다. 구현 모델은 GPT-5.6 sol, reasoning effort는 medium으로 사용한다.
