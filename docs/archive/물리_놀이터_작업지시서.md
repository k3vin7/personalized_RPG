# 물리 놀이터 작업 지시서 (Claude Code용)

> 대상: Godot 4 / GDScript 프로젝트를 처음부터 만드는 Claude Code 세션
> 근거 문서: `협동_액션_RPG_기획서_v0.3.md` (2장 이동, 7장 아군 상호작용, 9장 네트워크)
> 목표: 무기·스킬·몬스터 없이 **이동·점프·돌진·등반·힘 이벤트·던지기**를 2인 네트워크로 만져볼 수 있는 회색 박스 놀이터

---

## 0. Claude Code에게: 작업 규칙 (먼저 읽을 것)

1. **단계 순서대로 진행한다.** 한 단계의 "완료 조건"을 전부 확인하기 전에는 다음 단계로 넘어가지 않는다.
2. **각 단계가 끝나면 멈추고 보고한다.** 보고 형식은 맨 아래 "단계 보고 형식"을 따른다. 사용자가 확인하고 "다음"이라고 하면 진행한다.
3. **범위 밖 기능을 만들지 않는다.** 무기, 스킬 풀, QWER 스킬, 몬스터 AI, 성장, 저장, UI 꾸미기, 실제 지역 맵은 이번 범위가 아니다 ("이번에 만들지 않는 것" 참고).
4. **문서에 없는 결정이 필요하면 멈추고 묻는다.** 임의로 정하지 않는다. 단, 이 문서에 "기본값"으로 적힌 값은 그대로 쓴다.
5. **튜닝 값은 코드에 박지 않는다.** 모든 수치는 `PhysicsTuning` 리소스와 `CharacterStats` 리소스에서 읽는다. 디버그 패널에서 실행 중에 바꿀 수 있어야 한다.
6. **처음부터 네트워크를 전제로 짠다.** 1단계부터 플레이어 2명이 접속한 상태로 동작해야 한다. 혼자 하는 코드를 먼저 짜고 나중에 네트워크를 붙이지 않는다.
7. 정적 타입 GDScript를 쓴다 (`var speed: float = 6.0`). 물리 로직은 `_physics_process`에서만 처리하고, `_process`는 시각 효과에만 쓴다.
8. 각 단계 끝에 git 커밋을 남긴다 (커밋 메시지에 단계 번호).

## 5. 핵심 공식

모든 "힘 대 무게" 계산은 **함수 하나**를 통한다. 다른 곳에서 따로 계산하지 않는다.

```
total_weight = race_weight + gear_weight
ratio = strength / max(total_weight, 0.1)     # 기본값이면 1.0

ratio_mult(ratio, k) = clamp(1 + k * ln(ratio), ratio_mult_min, ratio_mult_max)
```

- 로그를 쓰는 이유: 비율이 커져도 효과가 완만하게 늘어나게.
- `ln(1) = 0`이라 기본값에서 배율은 정확히 1.0.

| 값 | 계산 |
| --- | --- |
| 점프 높이 | base_jump_height × ratio_mult(ratio, ratio_k_jump) |
| 점프 초기 수직 속도 | sqrt(2 × gravity × 점프 높이) |
| 이동 속도 | base_move_speed × ratio_mult(ratio, ratio_k_speed) |
| 수평 점프 거리 | 따로 계산하지 않는다. 이동 속도 × 체공 시간으로 **자연히** 나온다 |
| 밀기·던지기 속도 변화량 | 기본 power × ratio_mult(미는 사람 strength ÷ 대상 total_weight, ratio_k_jump) |

주의: 밀기·던지기는 **미는 사람의 근력**과 **대상의 무게**를 섞는다. 그래서 대상의 `CharacterStats`(특히 무게)가 모든 피어에 동기화되어 있어야 한다.

## 6. 플레이어 상태 머신

```
IDLE, MOVE, AIRBORNE, DASH, CLIMB, MANTLE, GRABBING, GRABBED, STUNNED, DEAD
```

| 상태 | 들어가는 조건 | 나가는 조건 |
| --- | --- | --- |
| IDLE | 지상, 이동 목표 없음 | 클릭 → MOVE, Space → AIRBORNE, F → DASH |
| MOVE | 지상, 이동 목표 있음 | 도착 → IDLE, Space → AIRBORNE, F → DASH, 등반 벽 도달 → CLIMB |
| AIRBORNE | 점프, 낭떠러지에서 떨어짐, 외부 힘으로 뜸 | 착지 → IDLE/MOVE, 벽에 닿고 등반 조건 충족 → CLIMB (이번 단계에선 공중 벽잡기 없음, 아래 참고) |
| DASH | 지상에서 F, 쿨다운 끝 | dash_duration 경과 또는 벽 충돌 → IDLE |
| CLIMB | 등반 벽에 붙음 | Space → AIRBORNE(벽에서 떨어짐), 지구력 0 → AIRBORNE, 위 모서리 도달 → MANTLE, 아래 끝 도달 → IDLE |
| MANTLE | 등반 중 위 모서리 | 짧은 자동 이동 후 IDLE |
| GRABBING | G로 대상을 잡음 | G → 던지기 후 IDLE, 대상이 탈출 → IDLE |
| GRABBED | 다른 플레이어가 잡음 | 던져짐 → AIRBORNE, 탈출 → IDLE |
| STUNNED | 지상에서 외부 힘 + 경직 플래그 | stun 시간 경과 → IDLE |
| DEAD | HP 0 또는 kill plane 아래 | respawn_delay 후 스폰 지점에서 IDLE |

상태 전이는 `player.gd`의 함수 하나(`change_state(new_state)`)로만 일어나게 한다. 상태는 네트워크로 동기화해서 상대 화면에서도 애니메이션 대용 표시(색, 라벨)가 맞게 한다.

## 단계 1. 프로젝트 골격 + 2인 접속 + 맵 + 카메라 + 클릭 이동

### 1-1. 네트워크 골격 (`autoload/net.gd`)
- `main.tscn`에 Host 버튼, Join 버튼, IP 입력칸(기본 127.0.0.1), 포트(기본 7777).
- Host: `ENetMultiplayerPeer.create_server(port, 4)`, 호스트 자신도 플레이어로 스폰.
- Join: `create_client(ip, port)`.
- 플레이어 스폰은 **호스트만** 한다. `MultiplayerSpawner`를 `playground.tscn`에 두고, 접속한 피어마다 `player.tscn` 인스턴스를 만든다. 노드 이름 = 피어 ID 문자열.
- 각 플레이어 노드는 `set_multiplayer_authority(peer_id)`. **자기 캐릭터 이동은 자기 클라가 권한**을 가진다 (기획서 9장).
- `MultiplayerSynchronizer`로 위치, 회전, 상태, `CharacterStats`(strength, race_weight, gear_weight), HP를 동기화한다.
- 원격 플레이어는 받은 위치를 그대로 대입하지 말고 짧게 보간한다 (`global_position = global_position.lerp(target, 보간계수)`).
- 접속 해제 시 그 플레이어 노드를 제거한다.
- `SceneMultiplayer.server_relay`는 켜둔다 (클라끼리 RPC를 호스트가 중계하도록).

### 1-2. 테스트 맵 (`playground.tscn`)
CSG나 기본 MeshInstance3D + StaticBody3D로 회색 박스 지형을 만든다. 치수는 아래대로.

| 구역 | 내용 | 확인할 것 |
| --- | --- | --- |
| 바닥 | 40 × 40m 평지 | 기본 이동 |
| 계단 | 높이 0.5 / 1.0 / 1.5 / 2.0m 단 4개, 각 3 × 3m | 점프 높이 한계 확인 |
| 틈 | 폭 2 / 3 / 4 / 5m 틈 4개, 틈 아래는 깊이 3m 구덩이(바닥 있음) | 수평 점프 거리 확인 |
| 등반 벽 A | 높이 6m, 폭 6m, 면이 카메라를 향함 (앞면) | 상하좌우 자유 등반 |
| 등반 벽 B | 높이 6m, 폭 6m, 면이 카메라 기준 옆을 향함 (옆면) | 수직 등반만 |
| 등반 벽 C | 높이 6m, 카메라 반대쪽을 향하는 면 (뒷면) | 투명화 + 등반 |
| 매끈한 벽 | 높이 4m, 레이어 2 (등반 불가) | 등반 안 되는지 |
| 낭떠러지 | 맵 한쪽 끝, 아래에 바닥 없음 (kill plane까지 낙하) | 낙사, 리스폰 |
| 높은 단 | 높이 5m 단 (계단 또는 등반으로 오름) | 낙하 피해 확인용 |
| 가림 벽 | 높이 5m 벽 여러 개, `occluder` 그룹 | 투명화 |
| 시간 경계 | 단계 8에서 추가 | |
| 돌 | 크기 다른 돌 3개 (무게 5 / 10 / 20) | 단계 7 |
| 허수아비 | 2개 | 단계 6 |
| 스폰 지점 | 맵 중앙 근처 Marker3D 4개 | |

- 바닥, 계단, 단에는 `NavigationRegion3D`로 내비메시를 굽는다. **틈과 낭떠러지 너머는 내비메시가 이어지지 않아야 한다** (일부러 도달 불가 상태를 만들기 위해).
- 등반 벽 표면 위는 내비메시에 포함하지 않는다.

### 1-3. 카메라 (`quarter_camera.gd`)
- 원근 카메라, FOV 40, 피치 약 55° 아래를 내려다봄, **회전 없음**.
- 자기 플레이어만 따라간다 (원격 플레이어는 따라가지 않음). 부드럽게 따라가되 지연은 짧게.
- 카메라 앞 방향(수평 투영)은 등반 면 분류에 쓰이므로 `get_camera_flat_forward()` 함수로 제공한다.

### 1-4. 클릭 이동 (`player_movement.gd`)
- 우클릭: `camera.project_ray_origin/normal`로 레이를 쏜다. 레이어 1·2·3·5만 검사하고, **현재 투명화 중인 벽은 exclude 목록에 넣는다** (단계 1-5와 연결).
- 레이가 바닥(레이어 1)에 맞으면 그 점을 목표로 `NavigationAgent3D.target_position` 설정.
- 레이가 등반 벽(레이어 3)에 맞으면 → 단계 4에서 처리. 이 단계에서는 벽 앞 바닥 지점으로만 이동.
- 우클릭을 누르고 있으면 0.1초마다 목표를 갱신한다 (롤처럼).
- 이동은 내비 경로의 다음 지점 방향으로 `velocity.x/z = 방향 × 이동속도`, `move_and_slide()`.
- 몸 방향은 이동 방향을 바라본다.
- Esc: 목표 취소.

### 1-5. 가림 처리 (`occlusion_fader.gd`, `dither_fade.gdshader`)

## 단계 2. 점프 + 근력/무게 공식 + 디버그 패널

### 2-1. 공식 함수
- `Tuning.ratio_mult(ratio: float, k: float) -> float` 를 autoload에 둔다 (5장 공식).
- `player.get_ratio() -> float` = strength / total_weight.
- `get_jump_height()`, `get_jump_velocity()`, `get_move_speed()`를 플레이어에 둔다. 다른 코드는 이 함수만 쓴다.

### 2-2. 점프 규칙 (기획서 2장)
Space를 누른 순간, 지상(IDLE/MOVE)일 때만:

| 상황 | 결과 |
| --- | --- |
| 이동 중 (수평 속도 > 0.1) | 현재 수평 속도 그대로 + 수직 속도로 점프 |
| 정지 + 이동 의도 없음 | 수직 점프 (수평 속도 0) |
| 정지 + 이동 의도 있음 | 의도 방향 × 이동 속도로 수평 속도를 주고 점프 |

**이동 의도 보존**
- 클릭 목표가 도달 불가면 (`NavigationAgent3D`의 최종 경로 끝점과 클릭 지점의 수평 거리 > 0.5m), 경로 끝(가장자리)에서 멈추되 `move_intent_dir = (클릭 지점 - 현재 위치)의 수평 정규화`를 저장하고 `move_intent_timer = move_intent_timeout`.
- 새 클릭, Esc, 타이머 만료 시 초기화.
- 가장자리에서 멈춘 상태로 Space → 의도 방향 달리기 점프.

**공중 규칙**
- AIRBORNE 동안 **자기 입력으로 수평 속도를 바꿀 수 없다**. 우클릭은 착지 후 목표로 예약만 된다.
- 몸 방향(yaw)은 공중에서도 커서 쪽으로 돌릴 수 있다 (나중에 공중 공격 방향용).
- 수직 속도에는 매 프레임 중력 적용.
- 외부 힘(단계 5)은 공중에서도 속도에 더해진다.

**자주 삑나는 부분**
- 점프하는 프레임에 `floor_snap_length`를 0으로 하고, 착지하면 원래 값으로 되돌린다. 안 그러면 점프 직후 바닥에 다시 붙는다.
- 점프 판정은 `is_on_floor()`가 아니라 "지상 상태 + 코요테 타임 0.1초"로 한다 (가장자리에서 한 프레임 늦게 눌러도 점프되게).
- 점프 입력 버퍼 0.1초 (착지 직전에 누른 Space도 착지 직후 점프).
- 공중에서 내비게이션 에이전트가 속도를 덮어쓰지 않게, AIRBORNE 상태에서는 내비 이동 코드를 아예 타지 않는다.

### 4-1. 붙기

- 붙는 높이는 현재 발 높이. 벽 면에서 0.35m 떨어진 위치에 몸을 고정하고, 몸은 벽을 바라본다.
- 붙을 때 그 벽의 **면 정보를 저장**: 법선 `wall_normal`(수평), 면 평면 `wall_plane = Plane(wall_normal, 접촉점)`, 벽 콜라이더, 면 분류(아래).
- 공중에서 벽에 닿아 자동으로 붙는 기능은 이번에 만들지 않는다 (나중에 결정).

### 4-2. 면 분류
```
f = camera.get_camera_flat_forward()   # 수평 정규화
d = abs(wall_normal.dot(f))
d > 0.7  → FRONT_OR_BACK (상하좌우 자유)
그 외     → SIDE (수직만)
```

### 4-3. 벽 위 이동
- **물리 레이캐스트를 쓰지 않는다.** 매달린 동안 우클릭은 카메라 레이와 `wall_plane`의 교점을 수학적으로 구한다 (`wall_plane.intersects_ray(origin, dir)`).
  - 이유: 뒷면 벽은 투명화 중이라 클릭 레이 exclude 목록에 들어가 있어서, 물리 레이로는 그 벽을 못 맞춘다. 평면 교점은 이 문제가 없다.
- 교점을 목표로 벽 면 위에서 climb_speed로 이동.
  - FRONT_OR_BACK: 목표 방향 그대로 (벽 면 위의 2D 이동)
  - SIDE: 목표의 높이 성분만 쓰고 좌우 성분은 0
- 이동 중 매 프레임 몸 뒤에서 벽 쪽으로 짧은 레이를 쏴서 아직 벽이 있는지 확인. 좌우로 벽이 끝나면 그 방향 이동을 막는다.
- 지구력: CLIMB 중 매초 stamina_climb_drain 감소, 0이면 AIRBORNE으로 떨어진다. 지상에서 회복.

### 4-4. 끝나는 방법

- **아래 끝**: 발이 바닥에 닿으면 IDLE.
- **Space**: 벽에서 떨어진다. 벽 법선 방향으로 2m/s, 위로 0 속도로 AIRBORNE. (벽점프 능력은 이번 범위 아님. `wall_jump_enabled: bool = false` 플래그만)
- 매끈한 벽(레이어 2)은 클릭해도 붙지 않는다.

## 단계 5. 힘 이벤트 시스템 (가장 중요)

넉백·밀기·던지기·낙하 사고를 전부 이 시스템 하나로 처리한다. 나중에 방패밀기, 적 넉백, 마법 바람도 여기로 들어온다.

### 5-1. 데이터
```
ForceEvent:
  kind: SHOVE | THROW | KNOCKBACK | DEBUG
  direction: Vector3        # 정규화. 위쪽 성분 포함 가능
  base_power: float         # m/s 단위 속도 변화량 기준값
  source_strength: float    # 미는 쪽 근력 (환경 힘이면 0 → 배율 1.0 처리)
  source_peer: int          # 보낸 피어 (0 = 환경/호스트)
  is_ally_source: bool      # 플레이어가 보낸 힘인지
  damage: float
  stun_time: float
```

### 5-2. 단일 진입점 (`autoload/force_system.gd`)
```
ForceSystem.send(target: Node, ev: ForceEvent)
```
- 대상이 플레이어면: 그 플레이어의 권한 피어에게 `rpc_id(target_authority, "receive_force", ev를 직렬화한 Dictionary)`. 대상이 자기 자신이면 로컬로 바로 적용.
- 대상이 허수아비·돌이면: 호스트에게 보낸다 (권한은 호스트).
- 다른 코드에서 대상의 velocity를 직접 건드리지 않는다. **반드시 이 함수를 거친다.**

### 5-3. 받는 쪽 처리 (대상의 권한 클라에서 실행)
```
power = base_power × ratio_mult(source_strength / 내 total_weight, ratio_k_jump)
dv = direction × power

if 내가 공중 (AIRBORNE 또는 GRABBED가 아닌 공중):
    velocity += dv                      # 궤도가 바뀐다
    if is_ally_source: 피해·경직 없음
    else: damage 적용
else (지상):
    velocity = dv                       # 밀려남
    if dv.y > 0.5: change_state(AIRBORNE)
    if not is_ally_source or ally_ground_damage: damage 적용
    if stun_time > 0 and (not is_ally_source or ally_ground_stun):
        change_state(STUNNED), stun_time 동안 입력 무시
        (STUNNED 중에도 물리 이동·마찰은 계속)
```
- 받는 쪽이 자기 무게로 계산하므로 무게가 항상 정확하다.
- 경직이 들어가면 진행 중이던 이동 목표·이동 의도는 지운다 (기획서: 쓰던 스킬은 끊기고 경직).
- CLIMB 중에 힘을 받으면 벽에서 떨어져 AIRBORNE.

### 5-4. 테스트 밀기 (`debug_shove`, E)
방패밀기가 아직 없으므로 임시 행동을 하나 만든다.
- 지상에서만. 앞쪽 1.5m, 90° 부채꼴 Area3D(레이어 7)로 판정.
- 맞은 대상(플레이어·허수아비·돌)마다 ForceEvent: kind=SHOVE, direction = (대상 - 나)의 수평 방향 + 위쪽 shove_up_bias 섞어 정규화, base_power=shove_power, source_strength=내 strength, is_ally_source=true, damage=shove_damage, stun_time=shove_stun_time.
- **판정은 미는 사람의 클라에서 한다** (기획서 9장 "느끼는 사람이 판정"). 맞았다고 판단하면 ForceSystem.send.
- 핑 차이 보정: 아군 대상 판정 범위를 시각 범위보다 0.3m 넓게 잡는다.

## 단계 6. 낙하 피해 + 리스폰

- AIRBORNE 진입 시 시작 높이를 기록하고, 공중 최고점을 계속 갱신한다.
- 착지 순간 `낙하 높이 = 최고점 - 착지 높이`. fall_damage_enabled이고 낙하 높이 > fall_damage_min_height면 `(낙하 높이 - min) × fall_damage_per_meter` 피해.
- 아군이 던지거나 민 경우도 똑같이 적용한다 (기획서: 낙사 있음, 나중에 패치).
- `global_position.y < kill_plane_y`면 DEAD → respawn_delay 후 비어 있는 스폰 지점에서 HP 가득 채워 리스폰.
- HP 0도 DEAD.
- 피해는 대상 권한 클라가 계산하고, HP는 동기화한다.

### 단계 6 완료 조건
- [ ] 5m 단에서 뛰어내리면 소량 피해, 4m 미만은 피해 없음
- [ ] 팀원이 날려서 높은 곳에서 떨어져도 피해가 들어간다
- [ ] 낭떠러지로 떨어지면 2초 뒤 스폰 지점에서 부활한다
- [ ] 디버그 플래그로 낙하 피해를 끌 수 있다

## 단계 7. 던지기 (돌, 팀원) + 탈출

### 7-1. 돌 (`rock.tscn`, `rock.gd`)
- RigidBody3D, 레이어 5, `weight` 필드 (5 / 10 / 20). 권한 = **호스트**.
- 클라에서는 돌을 `freeze`로 두고 호스트가 보낸 위치·회전을 보간만 한다 (클라가 직접 물리 시뮬레이션하면 떨림이 생긴다).

### 7-2. 잡기 (G)
- 지상에서 G: grab_range 안에서 커서와 가장 가까운 돌 또는 플레이어를 잡는다. 대상이 없으면 아무것도 안 함.
- 돌: 호스트에게 "잡기 요청" RPC → 호스트가 승인하면 돌을 잡은 플레이어 손 위치(머리 위 0.8m)에 붙여서 따라오게 함 (호스트가 위치 갱신).
- 플레이어: 대상의 권한 클라에 "잡힘" RPC → 대상은 GRABBED 상태가 되고, **잡은 사람이 동기화하는 손 위치를 따라간다**.
- GRABBING 중 이동 속도는 70%. 점프·돌진 불가.

### 7-3. 던지기 (GRABBING 중 G)
- 방향 = 커서 방향 수평 + throw_up_angle_deg 위쪽.
- 돌: 호스트에게 "던지기" RPC → 호스트가 freeze 해제, `linear_velocity = 방향 × throw_power × ratio_mult(내 strength / 돌 weight, ratio_k_jump)`.
- 플레이어: ForceSystem.send(대상, ForceEvent{kind=THROW, base_power=throw_power, source_strength=내 strength, is_ally_source=true, damage=0, stun_time=0}). 대상 클라는 GRABBED를 풀고 공중 상태로 이 힘을 받는다 (공중이므로 피해 없음).
- 던져진 팀원은 공중 상태라, **다른 팀원이 E로 한 번 더 밀어줄 수 있다** (단계 5 규칙 그대로).

### 7-4. 돌에 맞음
- 날아가는 돌이 플레이어나 허수아비에 닿으면, 호스트가 판정해서 ForceSystem.send(대상, KNOCKBACK, 돌 속도 방향, 돌 속도에 비례한 power, 피해 소량). source_strength는 0 (환경 힘 취급).
- 같은 돌이 같은 대상에게 0.5초 안에 두 번 맞지 않게 한다.

### 7-5. 탈출
- GRABBED 상태의 플레이어가 Space를 grabbed_escape_window 안에 grabbed_escape_presses번 누르면 풀려난다.
- 풀리면 잡은 사람 반대 방향으로 약하게 밀려나며 IDLE (잡은 사람은 IDLE).
- 탈출 진행도를 머리 위에 표시한다.

### 7-6. 예외 처리 (삑나기 쉬운 곳)
- 잡은 사람이 접속을 끊으면 → 잡힌 사람은 즉시 풀린다.
- 잡은 사람이 힘을 받아 경직되거나 떨어지면 → 잡고 있던 대상을 놓는다 (던지지 않고 떨어뜨림).
- 잡힌 사람이 다른 힘을 받으면 → 풀리고 그 힘을 받는다.
- 두 사람이 같은 대상을 동시에 잡으려 하면 → 대상 권한 쪽(돌은 호스트, 플레이어는 본인)이 먼저 도착한 요청 하나만 승인.
- 서로를 동시에 잡는 경우 → 먼저 잡힌 쪽이 GRABBED가 되면 GRABBING 요청은 거절.

### 단계 7 완료 조건
- [ ] 돌 3개를 잡아 던질 수 있고, 무거운 돌일수록 덜 날아간다
- [ ] 던진 돌이 허수아비·팀원에 맞으면 밀려나고 피해가 들어간다
- [ ] 팀원을 잡아 던질 수 있고, 무게가 무거운 팀원일수록 덜 날아간다
- [ ] 던져진 팀원을 공중에서 E로 밀면 한 번 더 날아간다
- [ ] 잡힌 쪽이 Space 연타로 빠져나올 수 있다
- [ ] 7-6의 예외 상황을 각각 재현해서 멈춤·꼬임이 없는지 확인했다 (보고 때 결과 표로)

## 단계 8. 시간 경계 (포트폴리오 첫 장면)

맵 한쪽에 "시간이 잘려 붙은 경계"를 하나 만든다. 기능은 단순하고 연출이 핵심이다.

- 서로 다른 두 구역을 붙인다: 한쪽은 초록 풀밭 바닥(높이 0), 다른 쪽은 모래색 바닥(높이 3m). 경계는 칼로 자른 듯한 **수직 단면**이다.
- 단면에는 지층 줄무늬가 보이는 머티리얼 (노이즈 기반 가로 띠 정도면 충분).
- 단면 앞에 얇은 쿼드를 세우고 `time_boundary.gdshader`로 일렁이는 굴절·빛 띠 효과 (화면 텍스처 UV를 시간에 따라 살짝 흔들기 + 가장자리 발광).
- 경계 근처에 떠 있는 먼지 파티클 (`GPUParticles3D`, 속도가 거의 0인 "멈춘 먼지").
- 3m 단면은 **등반 벽(레이어 3)**으로 만든다. 물리적 게이트 역할: 점프로는 못 오르고 등반이나 팀원 던지기로 넘어간다.
- 경계는 버그가 아니라 연출로 보여야 한다. 단면 모서리가 매끈하게 맞물리고 틈이 보이지 않게 한다.

### 단계 8 완료 조건
- [ ] 쿼터뷰 화면에서 한눈에 "땅이 잘려 붙었다"가 보인다
- [ ] 단면을 등반해서 위로 올라갈 수 있다
- [ ] 팀원을 던져서 위로 올려줄 수 있다
- [ ] 단면 주변 연출(일렁임, 멈춘 먼지)이 두 클라에서 같게 보인다
- [ ] 10초 정도 영상으로 찍을 만한 장면이 나온다 (사용자 판단)
