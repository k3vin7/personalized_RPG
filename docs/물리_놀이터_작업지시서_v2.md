> 대상: 이미 만들어진 Godot 프로젝트(PLAYTEST_01 기준)를 이어서 작업하는 Claude Code 세션
> 근거 문서: **판타지 RPG 기획서 v0.6** (Claude Docs). 이전 근거였던 `협동_액션_RPG_기획서_v0.3.md`는 폐기
> 목표: 무기·몬스터 없이 **이동·점프·돌진·밀치기·잡기·던지기·등반·낙하**를 혼합 판정 구조의 2인 네트워크로 만져볼 수 있는 회색 박스 놀이터
> 이번 판의 핵심 변경: **판정 권한이 "느끼는 사람이 판정" → "혼합"으로 바뀐다.** 이동만 내 클라, 나머지는 서버.

## 0. 작업 규칙 (먼저 읽을 것)

1. **단계 순서대로 진행한다.** 한 단계의 완료 조건을 전부 확인하기 전에는 다음 단계로 넘어가지 않는다.
2. **각 단계가 끝나면 멈추고 보고한다.** 형식은 맨 아래 "단계 보고 형식". 사용자가 "다음"이라고 하면 진행한다.
3. **범위 밖 기능을 만들지 않는다** ("이번에 만들지 않는 것" 참고).
4. **문서에 없는 결정이 필요하면 멈추고 묻는다.** 단, 이 문서에 "기본값"으로 적힌 수치는 그대로 쓴다.
5. **이미 구현된 것을 갈아엎지 않는다.** PLAYTEST_01에 기록된 수정 사항(커서 조준 점프, 커서 거리 돌진, 120 Hz, 경로 선행 소비, 가림 처리 일반화, 한글 IME 대응 등)은 유지한다. 바꿔야 하면 이유를 보고하고 묻는다.
6. 정적 타입 GDScript. 물리 로직은 `_physics_process`에서만, `_process`는 시각 효과에만.
7. 각 단계 끝에 git 커밋 (메시지에 단계 이름).

### CLAUDE.md 절대 규칙 (기획서 v0.6과 동일, 프로젝트 CLAUDE.md에도 그대로 넣는다)

- 클라이언트는 자기 이동·점프·돌진만 정하고(서버가 속도·거리 검사), 명중·밀기·최초 획득·보상 등 나머지 판정은 서버가 한다.
- 최초 판정은 DB 유일 제약으로만 한다. 게임 서버 if문 금지. (이번 범위엔 해당 기능 없음)
- 사건 로그는 추가만 한다. 수정, 삭제 금지. (이번 범위엔 해당 기능 없음)
- 조건과 세계 상태는 서버 DB의 데이터로 둔다. 히든 조건, 대사, 보상은 클라이언트에 넣지 않는다.
- 밀기·던지기·충돌·피격은 힘 이벤트 함수 하나를 거친다. 동작 전용 예외 금지.
- 튜닝 값은 코드에 박지 않고 데이터와 디버그 슬라이더로 뺀다.
- 맵은 지역 조각 모듈로 만든다. 막 전환은 조각 교체 + 플래그 변경.
- 능력은 겹 구조, NPC 관계는 상태 칸, 시간은 서버 타이머.
- 새 기능은 만들 때마다 2인 접속으로 확인한다.
- 하지 말 것: 서버 분할, 아트 작업, 단계 완료 전 다음 단계 진행.

## 3. 판정 권한 (혼합, 확정)

| 판정 | 누가 | 비고 |
| --- | --- | --- |
| 내 이동·점프·돌진·등반 위치 | **내 클라** | 반응성 때문. 서버는 결과를 검사만 한다 |
| 내 이동이 말이 되는지 | **서버** | 속도·거리 상한 검사. 남이 준 힘(아래 4장)은 서버가 자기가 보낸 힘 이벤트를 알고 있으므로 상한에 더해준다 |
| 공격·밀치기 명중 | **서버** | |
| 흘리기·완벽 방어·공격 잡기 성공 | **서버** | 판정 시간창은 지연 100~200ms 기준으로 넉넉하게 |
| 잡기·던지기 성립, 탈출 | **서버** | |
| 피해·HP·사망 | **서버** | |
| 투사체 생성·쳐내기·명중 | **서버** | 지금은 맞는 쪽 클라가 판정함 → 단계 B에서 옮긴다 |
| 돌·허수아비 등 물체 | **서버** | |
| 드랍·보상·최초 획득·히든 | **서버** (절대) | 이번 범위엔 없음 |

### 힘 이벤트의 흐름

1. 서버가 "밀치기가 맞았다"를 판정한다.
2. 서버가 대상의 소유 클라에 힘 이벤트를 보낸다.
3. 대상 클라가 자기 무게로 속도 변화를 계산해 적용한다 (이동 권한이 그쪽에 있으므로).
4. 서버는 그 힘 이벤트를 기억해 두고, 대상의 이후 속도 검사 상한에 반영한다.

플레이어가 아닌 대상(돌, 허수아비)은 서버가 직접 적용한다.

## 4. 물리 규칙 (기획서 v0.6)

**"이거 되나?" 해보면 진짜 된다. 동작 전용 예외는 두지 않는다.**

| 규칙 | 내용 |
| --- | --- |
| 근력 ÷ 무게 | 점프 높이, 이동 속도, 돌진 거리, 밀기·던지기 힘이 전부 이 하나로 정해진다 |
| 무게 | 캐릭터 체중 + 장비 + 들고 있는 것 |
| 속도 → 피해 | 빠르게 움직이며 칠수록 세다. 돌진, 낙하, 동료가 밀어준 것 전부 포함 (공격이 생기면 적용. 이번 범위는 계산 함수 자리만) |
| 높이 → 피해 | 위에서 내려칠수록 세다 (위와 같음) |
| 밀림 | 미는 힘 ÷ (내 무게 × 버티는 힘). 밀기, 막기, 피격, 충돌이 전부 같은 힘 이벤트 함수를 거친다 |
| 공중 | 자기 입력으로 수평 궤도를 못 바꾼다. 외부 힘을 받으면 바뀐다 |
| 도약 한계 | 내 힘으로 낸 속도의 합은 근력 ÷ 무게 한계를 넘지 못한다. 돌진 점프는 멀리, 제자리 점프는 높이. **남이 준 힘은 한계와 무관하게 더해진다** |
| 발판 | 밟을 수 있는 표면을 밟으면 다시 뛴다. 움직이는 발판은 속도를 물려준다. 머리 밟기는 0.5초 |
| 대가 | 낙하 피해, 반동은 항상 있다 |
| 피해 상한 | 없다 |

### 능력치 (놀이터에서 쓰는 것만)

| 능력치 | 놀이터에서 정하는 것 |
| --- | --- |
| 근력 | 점프 높이, 이동 속도, 돌진 거리, 밀기·던지기 힘, 도약 한계, 들 수 있는 무게, 버티는 힘 |
| 지구력 | 스태미나 총량과 회복 (돌진, 등반, 들기, 충전, 탈출에 사용) |

민첩·지능은 이번 범위 밖. `CharacterStats`에 필드 자리만 둔다.

### 공식 (현재 기본값, 튜닝 대상)

```
total_weight = body_weight + gear_weight + held_weight
ratio = strength / max(total_weight, 0.1)          # 기본값이면 1.0
ratio_mult(ratio, k) = clamp(1 + k * ln(ratio), ratio_mult_min, ratio_mult_max)
```

- 이 함수 하나로만 계산한다. 다른 곳에서 따로 계산하지 않는다.
- 클램프 폭(0.7~1.3)은 이전 지시서의 기본값이다. 기획에서 확정된 수치가 아니므로 디버그 슬라이더로 조절 가능하게 둔다.

## 단계 B. 혼합 판정으로 전환 + 네트워크 검증

### B-1. 구조
- 서버 판정 로직은 서버 노드 하나에 모은다. 호스트 화면의 플레이어도 다른 클라와 똑같이 "클라 하나"로 취급한다 (나중에 헤드리스로 떼어낼 때 수정할 곳이 없게).
- 클라는 공격·방어·상호작용을 **의도**로 보낸다 ("이 방향으로 횡베기", "방패 올림 시각"). 결과는 서버가 내려준다.
- 투사체 생성·쳐내기·명중을 서버로 옮긴다. 방패 완벽 방어 판정 시간은 서버가 받은 "방패 올림 시각"과 명중 시각으로 계산한다.
- 이동은 내 클라 그대로. 서버는 매 동기화마다 이동 거리 ÷ 시간이 `근력 기반 상한 × server_speed_tolerance + 최근 서버가 보낸 힘`을 넘는지 검사하고, 넘으면 로그를 남긴다 (이번 단계에선 되돌리지 않고 기록만).

### B-2. 검증
- 클라 2개 접속, 이동·점프·돌진·충돌 동기화.
- **지연 100ms / 200ms** 두 조건 (지연 시뮬레이션 도구 사용, 방법은 보고에 적는다).
- 한 명이 끊겼다 다시 들어와도 문제없다.
- 사로에서 두 사람이 같은 탄을 막거나 맞을 때 결과가 양쪽 화면에서 같다.
- PLAYTEST_01의 "미확인" 항목 중 2인 관련 항목을 이번에 확인하고 표를 갱신한다.

### 단계 B 완료 조건
- [ ] 판정 위치가 3장 표와 일치한다 (보고에 전후 비교표)
- [ ] 지연 200ms에서 이동·점프·돌진이 크게 깨지지 않는다
- [ ] 지연 200ms에서도 완벽 방어가 "납득되는" 빈도로 성공한다 (판정 시간 조정값 보고)
- [ ] 재접속 정상
- [ ] 서버 속도 검사가 정상 플레이에서 경고를 내지 않는다

## 단계 C. 조작 맞추기

- **Space 톡/꾹**: 누른 시간이 `jump_hold_time` 미만이면 낮은 점프, 이상이면 높은 점프. 지상에서 누르는 순간 바로 뜨고, 떼는 시점에 상승을 끊는 방식(가변 점프)으로 구현한다. 커서 조준 방향 규칙은 그대로.
- **우클릭 꾹**: 누르고 있으면 커서를 계속 따라간다 (기존 0.1초 갱신 등 구현돼 있으면 유지).
- **돌진 최대 거리 = dash_max_distance_base × 근력 배율.** 커서가 더 가까우면 커서까지 (기존 규칙 유지).
- **도약 한계**: 내 입력으로 낸 수평·수직 속도의 합이 근력 ÷ 무게 한계를 넘지 않게 한다. 돌진 중 점프는 이 한계 안에서 허용 (기존 `allow_dash_jump` 플래그가 있으면 이 규칙으로 대체하고 보고).

### 단계 C 완료 조건
- [ ] 톡 점프와 꾹 점프 높이 차가 눈에 보인다 (실측값 보고)
- [ ] 근력 슬라이더를 올리면 돌진 최대 거리가 늘어난다
- [ ] 돌진 점프는 멀리, 제자리 점프는 높이 가고, 둘 다 한계를 넘지 않는다
- [ ] 2인, 지연 200ms에서 확인

## 단계 D. 힘 이벤트 + 밀치기

### D-1. 힘 이벤트 (단일 진입점)
```
ForceEvent:
  kind: SHOVE | THROW | KNOCKBACK | RECOIL | DEBUG
  direction: Vector3      # 정규화
  base_power: float
  source_strength: float  # 환경 힘이면 0 → 배율 1.0
  source_peer: int
  is_ally_source: bool    # 아군 = 같은 파티원만 (놀이터는 디버그로 파티 지정)
  damage: float
  stun_time: float
```
- `ForceSystem.send(target, ev)`만 대상 속도를 바꾼다. 다른 코드에서 남의 velocity를 직접 건드리지 않는다.
- **서버만 send를 호출한다.** 대상이 플레이어면 소유 클라로 보내고, 물체면 서버가 직접 적용한다 (3장 흐름).
- 받는 쪽: `밀림 = base_power × ratio_mult(source_strength / 내 total_weight) ÷ 버티는 힘`.

| 받는 쪽 상태 | 결과 |
| --- | --- |
| 공중 | 속도에 더한다 (궤도 변경). 파티원이 보낸 힘이면 피해·경직 없음, 파티원이 아니면 공중이어도 피해 |
| 지상 | 속도를 이 값으로 바꾼다. 위쪽 성분이 크면 공중으로. 아군이라도 `ally_ground_damage / stun` 플래그대로 피해·경직 |
| 등반 중 | 벽에서 떨어진다 |

### D-2. 밀치기 (E)
- 커서 방향 **직사각형** 판정 (`shove_range × shove_width`). 공중 사용 가능.
- 반동: 미는 사람에게 반대 방향 `RECOIL` 힘 이벤트 (`shove_recoil` 비율).
- **근처에 점프한 아군이 있으면** 방향을 위로 `shove_ally_launch_angle_deg`만큼 보정해 발판 역할을 한다 (별도 "받치기" 기술 없음).
- 판정은 클라가 의도("이 방향 밀치기")를 보내고 서버가 한다.

### D-3. 발판·머리 밟기
- 밟을 수 있는 표면(플레이어 머리 포함)에 위에서 내려앉으면 다시 뛴다. 머리 밟기는 `head_stomp_time` 동안만 유효.
- 움직이는 발판(움직이는 플레이어 포함)은 그 속도를 물려준다.

### D-4. 허수아비
- 서버 소유. 힘 이벤트를 받으면 같은 규칙으로 밀려나고 HP가 깎인다. 일정 시간 뒤 원위치.

### 단계 D 완료 조건
- [ ] 허수아비를 밀면 밀려나고 HP가 깎인다. 미는 사람도 반동으로 조금 밀린다
- [ ] 점프한 팀원을 밀면 위로 보정돼 높이·멀리 날아가고 피해가 없다
- [ ] 지상 팀원을 밀면 밀려나고 피해·경직. 플래그로 끄면 위치만 밀린다
- [ ] 근력↑·무게↓일수록 멀리 날아간다
- [ ] 팀원 머리를 밟고 한 번 더 뛸 수 있다
- [ ] 두 화면에서 궤적이 같다
- [ ] ForceSystem을 거치지 않고 남의 velocity를 바꾸는 코드가 없다 (grep 결과 첨부)

## 단계 E. 잡기·던지기 (한 키)

### E-1. 잡기 (G)
- 커서와 가장 가까운 대상(돌, 플레이어, 허수아비)을 `grab_range` 안에서 잡는다. 서버가 승인한다.
- **한손 잡기는 두손 잡기보다 근력이 `grab_one_hand_strength_mult`배 필요하다.** 한 손에 무기를 들고 있으면 한손 잡기 (놀이터에는 무기 장착 상태 플래그만 두고 디버그로 토글).
- 대상 무게가 들 수 있는 한계를 넘으면 못 든다.
- 들고 있는 동안 **내 무게 = 내 무게 + 든 것 무게** (이동·점프가 그만큼 둔해진다).
- 공격 잡기(적 공격 타이밍에 누르면 그 공격을 막으며 붙잡기, 근력이 공격의 힘보다 커야 함)는 **적 공격이 생기는 전투 기본 단계에서 붙인다.** 이번엔 잡기 판정 함수에 "공격의 힘과 비교" 자리만 만들어 둔다.

### E-2. 내려놓기·던지기 (잡은 상태에서 G를 누름)
| 누른 시간 | 결과 |
| --- | --- |
| `throw_hold_threshold`(1초) 전에 뗌 | 내려놓기 |
| 1초 이상 누르고 뗌 | **포물선 던지기.** 커서 = 착지점, 충전 = 최대 사거리 |
| Shift를 누른 채 위와 같이 | **직선 던지기.** 커서 = 방향, 충전 = 세기·피해 |

- 충전 중에도 이동할 수 있다.
- 던지기는 서버가 `THROW` 힘 이벤트(플레이어) 또는 물체 속도 설정(돌)으로 처리한다. 힘 = 내 근력 ÷ 대상 무게.
- 던져진 팀원은 공중이므로 다른 팀원이 한 번 더 밀어줄 수 있다 (D 규칙 그대로).
- 잡은 상태에서 꼭 던질 필요는 없다. 무기가 생기면 다른 손 무기로 그대로 칠 수 있게, 잡기 중 다른 행동을 막는 코드를 넣지 않는다.

### E-3. 돌에 맞음
- 날아가는 돌이 대상에 닿으면 서버가 `KNOCKBACK` 힘 이벤트 (돌 속도 방향, 속도 비례 힘). 같은 돌·같은 대상 0.5초 중복 금지.

### E-4. 탈출
- 잡힌 쪽이 Space를 `escape_window` 안에 `escape_presses`번 누르면 풀린다. 진행도를 머리 위에 표시.

### E-5. 예외 (서버가 처리)
- 잡은 사람 접속 끊김 → 즉시 풀림.
- 잡은 사람이 경직·낙하 → 던지지 않고 떨어뜨림.
- 잡힌 사람이 다른 힘을 받음 → 풀리고 그 힘을 받음.
- 같은 대상을 동시에 잡으려 함 → 서버에 먼저 도착한 요청만 승인.
- 서로 동시에 잡음 → 먼저 승인된 쪽만 성립.

### 단계 E 완료 조건
- [ ] 1초 전에 떼면 내려놓고, 1초 넘게 누르면 포물선, Shift면 직선
- [ ] 포물선은 커서 지점 근처에 떨어지고, 충전이 짧으면 커서까지 못 간다
- [ ] 무거운 돌·팀원일수록 덜 날아가고, 들고 있으면 내가 느려진다
- [ ] 한손 잡기 토글 시 근력이 부족하면 못 든다
- [ ] 던진 팀원을 공중에서 밀어 한 번 더 보낼 수 있다
- [ ] E-5 예외를 각각 재현해 결과 표로 보고

## 단계 F. 등반 (표시된 면만)

- **등반은 표시된 면에서만 된다.** 등반 가능 면은 전용 레이어/그룹 + 눈에 보이는 표시(색이나 질감)를 함께 준다. 표시 없는 벽은 클릭해도 붙지 않는다.
- 붙기: 등반 면을 우클릭 → 걸어가서 붙음.
- 벽 위 이동: 매달린 동안 우클릭은 **카메라 레이와 붙은 벽 평면의 교점**으로 계산한다 (물리 레이 아님. 투명화된 벽도 클릭되게).
- 면 방향 규칙 (v0.2에서 정한 것, 유지): 카메라를 향한 앞면·뒷면은 상하좌우, 옆면은 수직만.
- 지구력을 소모하고, 0이면 떨어진다. 위 모서리에 닿으면 자동으로 올라선다. Space로 벽에서 떨어진다.
- 매달린 중에 힘 이벤트를 받으면 떨어진다 (D 규칙).

### 단계 F 완료 조건
- [ ] 표시된 면만 붙고, 표시 없는 벽은 안 붙는다
- [ ] 앞면 상하좌우, 옆면 수직만
- [ ] 투명화된 뒷면도 클릭으로 이동된다
- [ ] 지구력이 다 떨어지면 떨어지고, 모서리에서 올라선다
- [ ] 두 화면에서 위치가 맞다

## 단계 G. 낙하 피해·사망·리스폰

- 공중 최고점 기록 → 착지 시 `낙하 높이 > fall_damage_min_height`면 `(높이 - min) × fall_damage_per_meter` 피해. 피해 계산과 HP는 서버.
- 아군이 던지거나 민 경우도 똑같이 적용 (`ally_fall_death` 플래그).
- 맵 가장자리 밖(공백 지대에 해당하는 낭떠러지)으로 떨어지면 사망 → 리스폰. HP 0도 사망.

- [ ] 낭떠러지 낙하 → 리스폰
- [ ] 플래그로 끌 수 있다
