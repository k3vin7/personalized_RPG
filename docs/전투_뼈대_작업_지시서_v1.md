# 전투 뼈대 작업 지시서 v1 — 단계 C-1 (Claude Code용)

> 대상: `physics_playground` 프로젝트 (기준 코드). 물리 놀이터 v4 단계 H·N·M 전부 완료 + C-0(SkillDef 스키마·타격 피드백·검 막대 호·범위 표시) 완료 전제
> 근거 문서: **판타지 RPG 기획서 v0.6** (Claude Docs, 2026-11-02 상태) + **기획 결정 추적표 v5.1** (`docs/` 엑셀, '기술 표' 탭). 지시서 v1~v4는 규칙 참고용으로만
> 이 지시서의 범위: **C-1만.** 검·방패·맨손 평타 + 피격·HP·방어력 + 스태미나 소모 + 치명타 + 돌진 조합 + 타격 피드백 연결. 허수아비 상대. 몬스터(C-2), 활(C-3), 스태프(C-4), 레벨·드랍·보스(C-5)는 다음 지시서
> 단계 라벨: C-0 준비 → **C-1** → C-2 검병+숙련 → (중간 손맛) → C-3 → C-4 → C-5 → (무기 들고 손맛) → 저장·사건 로그

---

## 0. 작업 규칙 (v4와 같음 + 셋 추가)

1. **단계 순서대로.** C-1 안의 소단계 C-1a → C-1e 순서. 각 소단계 끝나면 보고하고 **멈춘다.** 다음 소단계는 사용자가 "진행"이라고 한 뒤.
2. **동작 전용 예외 코드 금지.** 새 기술은 기존 규칙(힘 이벤트, 근력÷무게, 허용치, 상태 머신, 공격 예약 구조)의 조합으로만. 예외가 꼭 필요하면 멈추고 묻는다.
3. **판정은 서버.** 피해·치명타·흘리기 성공·스태미나·HP·사망 전부 서버 소유. 클라는 의도(어느 칸을 어느 방향으로)만 보낸다. 타격 피드백(히트스탑·플래시·숫자·흔들림)은 클라 전용이고 판정과 분리.
4. **기술 표가 곧 데이터.** 추적표 '기술 표' 탭의 한 행 = SkillDef 리소스(.tres) 하나. 열 이름과 1:1. **비어 있거나 "-"인 수치는 임의로 정하지 말고 멈추고 묻는다.** 하늘색 칸은 사용자가 아직 확정 안 한 임시값이라 전부 `Tuning.server` 슬라이더로 빼서 손맛 때 바꿀 수 있게 한다(코드에 숫자 박지 않음).
5. **손맛 전까지 기존 슬라이더 기본값 고정.** tolerance_per_strength 0.12, race_tolerance_mult 1.0, race_move_mult 1.0, ratio_k_jump/speed 0.35/0.30. 건드리지 않는다.
6. **바꾸기 전·후 실측 필수.** 기존 검사 세트(E·DK·M·N·H)는 전부 통과 상태를 유지. 회귀가 나면 그 소단계는 끝난 게 아니다.
7. `docs/`는 사용자가 관리한다. 건드리지 않는다. Godot **4.7.1**로만 연다. `project.godot` diff가 비어 있는지 보고 때마다 확인.
8. 완료 조건은 "동작한다"가 아니라 **"`--auto-only=C1x` 검사 통과"**다. 소단계마다 검사 세트를 먼저 짜고 구현한다.

## 2. 8칸 구조 (M 단계 슬롯 재사용)

- 한손 검 + 보조 방패 = 검 4 + 방패 4. 보조 손이 비면 방패 4칸 자리에 맨손 4(밀치기·잡기·주먹·발차기). 맨손+맨손 = 맨손 4 + 빈 4.
- 무기 선택대(서버 승인)에 검·방패 추가. 방패 던지기로 방패가 바닥에 떨어지면 **보조 손 칸이 즉시 맨손 4로 바뀌고**, 주우면(잡기 키로 집기 = 돌 규칙) 돌아온다.
- 입력은 M 단계 그대로: 키 → (스마트키 꺼짐) 범위 표시 → 좌클릭 확정. 흘리기·방패 들기는 범위 표시 없음(누르는 순간).
- 범위 표시 모양(C-0 데이터): 찌르기 직선 막대, 횡베기 수평 부채꼴, 종베기 좁은 전방 직사각형, 방패 밀기 직사각형, 던지기 직선, 찍기 원.

## 4. 소단계

### C-1a — 능력치·HP·스태미나 재편 + 무기 공격력·방어력 + 피해 공식
- 종족 표에 체력 열 추가(임시 = 지구력). HP 출처를 지구력 → 체력으로. 스태미나 = 지구력 × (1+α).
- 능력치 구조: 종족 기본 + 배분 포인트 × 가중치. 배분은 서버 소유, C-1엔 전부 0.
- `WeaponDef`(공격력·손 요구) + SkillDef에 공격 태그·`stun_on_hit`·스태미나 필드. C-0 스키마에 없던 열이면 추가.
- 서버 피해 함수 하나: `apply_hit(attacker, target, skill, ctx)` → 계수×공격력 → 속도/높이 보정 → 치명타 → 방어력 → HP 차감 → 넉백은 기존 힘 이벤트로. **이 함수 밖에서 HP를 깎는 코드 금지.**
- 허수아비·캐릭터 방어력 슬라이더, 캐릭터 HP 바(클라).
- **검사 C1a**: 피해 공식 표 — (공격력 10, 방어 0)=10 / (10, 100)=4.75 / (10, 400)=0 / (30, 400)=4.4 (소수 둘째 자리 비교). 강제 치명타 시 ×1.5. 인간 HP 105·스태미나 101.5 ± 0.1. 종족 바꿔도 HP가 체력 열에서 나오는지. 2피어 동기화.

### C-1b — 검 평타 4
- SkillDef 4개를 표에서 로드. 선딜/후딜/쿨/스태미나는 M 단계 기술 슬롯 상태 머신 그대로.
- 판정: 찌르기 직선 캡슐 스윕, 횡베기 수평 부채꼴(점프 중 = 발이 땅에서 뗀 대상 제외), 종베기 수직 부채꼴(공중 포함). 범위 모양은 C-0 데이터 참조.
- 찌르기 속도 보정: 시전 **의도 시점** 서버가 본 수평 속도.
- 흘리기: M-7 예약 구조. 창 안에 들어온 **공격 이벤트**(허수아비 강타 포함)를 무효화 + 공격자에게 `stun(원래 후딜 끝까지)`. 창 밖이면 후딜 0.4. 경직은 기존 튕겨나감 경직과 같은 상태(새 상태 금지).
- 검 막대 호 데이터 4개 + 잔상(C-0 레이어 연결). 타격 피드백 연결.
- **검사 C1b**: 각 기술 사거리 안/밖 명중 여부, 횡베기가 점프 중 허수아비를 안 맞히는지, 종베기가 공중 허수아비(발판 위)를 맞히는지, 찌르기 정지 vs 달리기 피해 차이 = 보정식과 일치, 흘리기 창 안(성공·경직 길이 = 강타 후딜 0.5)·밖(실패·후딜 0.4), 스태미나 0에서 시전 거부, 2피어.

### C-1c — 방패 4
- 들기: 자세 완성도 0→100% 0.2/0.6초, 막기 중 받아낸 피해×0.5 스태미나, 0 되면 풀림 + 회복 전 못 듦. 막아도 밀림 공식.
- 밀기: 힘 이벤트 재사용(놀이터 밀치기와 같은 함수), 돌진 조합 연결.
- 던지기: 방패를 **돌과 같은 물체**로 발사(던지기 코드 재사용, 직선). 떨어진 방패는 잡기 키로 줍기. 보조 손 칸 전환.
- 찍기: 공중 가능, 낙하 높이 보정.
- **검사 C1c**: 자세 0%/100% 밀림 거리 차, 스태미나 0 시 막기 풀림 + 못 듦, 던지기 후 칸이 맨손 4로 / 줍기 후 복구, 찍기 높이 0m vs 2m 피해 차 = 보정식, 2피어.

### C-1d — 돌진 조합 + 맨손 스태미나 + 발차기 결과
- 돌진 후 0.15초 창(클라 입력 간격, 서버는 간격만 검사). 조합 배율 선형. 밀기·찌르기·주먹에 적용.
- 맨손 4에 스태미나 열 적용. 발차기 넘어짐 1.0/기상 0.3 확인(이미 구현이면 검사만).
- **검사 C1d**: 돌진 후 0.10초 평타 = 조합 ON(배율 계산 일치), 0.20초 = OFF, 지연 200ms 프록시에서도 창 판정이 클라 간격 기준인지.

### C-1e — 사망·리스폰 + 손맛 준비
- HP 0 → DEAD 상태(기존 DOWNED와 별개), 리스폰은 스폰 지점. 페널티 없음(C-2에서).
- 디버그 패널에 "전투 튜닝(서버 승인)" 절: 무기 공격력, 방어력, crit_base, crit_per_agility, k_hp, α, stat_point_weight, 속도/높이 보정 계수, 흘리기 창, 돌진 조합 배율, 타격 피드백 6종(로컬).
- **검사 C1e**: HP 0 → DEAD → 리스폰 → HP/스태미나 풀, 2피어 중 한 명 사망 시 다른 피어 화면 일치.
- 전체 회귀: E·DK·M·N·H 전부 통과.
