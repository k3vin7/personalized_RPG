# T-1 작업 지시서 — 지형 시스템

작성 2026-11-04. C-1g e(카메라 줌) 완료 뒤 시작한다 — 각 하한이 정해져야 지평선·맵 끝 처리를 정할 수 있다.

## 목적
1막 첫 지역(시작 마을 → 동쪽 평지 → 숲)을 지을 수 있는 지형 바탕을 만든다. **야외는 Terrain3D, 도시·건물·조각 경계는 CSG/메시.** 둘이 한 씬에 섞인다.

## 건드리지 않는 것
- 전투·조작·스킬 — 전부 그대로
- 물리 놀이터 규칙 — 등반 가능 벽(바위, 눈으로 구분)은 모든 수직면을 오를 수 있고, 미끄러운 벽은 못 오른다. 낙하 피해·힘 이벤트 그대로
- 서버 권위 — 지형 충돌은 서버와 클라가 같은 데이터를 쓴다

## 공통 규칙
- 숫자는 전부 디버그 패널 슬라이더. 아래는 기본값
- 소단계(a~f) 하나 끝낼 때마다 **검사 → 보고 → 정지**. 다음 소단계는 승인 뒤
- 스크린샷은 안 찍는다. 내가 직접 본다. 숫자로 검사할 수 있는 건 헤드리스 검사로

## a. Terrain3D 설치·호환
- 현재 프로젝트의 Godot 버전에 맞는 Terrain3D 릴리스를 고른다. 릴리스 노트에서 지원 버전을 확인하고 보고
- GDExtension 로딩 확인. **헤드리스 검사 실행에서도 뜨는지** 확인 — 안 뜨면 지형 검사를 별도 레인으로 분리하고 그 사실을 보고
- 설치 경로, 버전, 알려진 제한(예: 충돌 생성 방식, 서버 전용 모드 여부)을 적는다
- 검사: 빈 지형 씬이 호스트·클라 둘 다에서 열리고, 기존 검사(C0·C1b·M·C1g) 회귀 0 실패

## b. 테스트 지역 하나
- 평지 + 완만한 언덕 + 숲 바닥. 텍스처 3종(풀·흙·돌)으로 구분만 하면 된다. 아트는 안 한다
- 걷기 가능 경사 한계: 기본 **40°** 슬라이더. 넘으면 미끄러져 내려온다(등반 아님 — 등반은 메시 벽에서만)
- 캐릭터 이동·점프·돌진·낙하 피해·잡기·던지기(돌)가 지형 위에서 그대로 동작
- 서버·클라 지형 충돌 일치: 클라가 보는 캐릭터 위치와 서버 판정 위치의 높이 차 보고
- 검사: 허수아비 3개를 언덕 위·아래·경사면에 놓고 횡베기 판정이 높이 차 때문에 빗나가지 않는지. 언덕 위에서 뛰어내려 낙하 피해가 들어가는지

## c. 조각 경계
- 세계관 규칙: 조각 경계는 단차·절벽이 되기도 하고, 바위가 잘려 있거나 갑자기 물이 생기는 식으로도 드러난다. **절벽만 반복되지 않게.** 시각 효과는 없고 "좀 이상하게 붙어 있다" 정도
- 경계 메시 3종을 만든다: ① 단차·절벽(잘린 산 단면) ② 잘린 바위 ③ 갑자기 생기는 물. 전부 CSG/메시
- 절벽은 **등반 가능 벽(바위)**과 **미끄러운 벽** 둘 다 되게 — 머티리얼이나 태그 하나로 구분, 눈으로 구분됨
- 검사: 등반 가능 절벽은 끝까지 오르고, 미끄러운 절벽은 못 오르고, 물은 들어가면 헤엄치거나 막히거나 — 현재 물 규칙이 없으면 "막힘"으로 두고 보고

## d. 카메라와 지형
- e에서 정한 각 하한 기준. 최대 확대·최소 각에서 **지평선·맵 끝·하늘이 어떻게 보이는지**를 먼저 보고
- 처리 규칙 둘: ① 안개(거리 슬라이더, 기본 = 카메라 거리의 3배) ② 맵 가장자리를 지형으로 높여 끝이 안 보이게(높이 슬라이더). 하늘은 단색 또는 그라디언트, 스카이박스는 안 한다
- 캐릭터를 가리는 지형·벽은 기존 투명 처리 규칙 그대로. 지형(Terrain3D)이 가릴 때도 되는지 확인
- 검사: 최대 확대에서 안개·가장자리가 맵 끝을 가리는지. 가장자리 높이기가 등반 벽으로 오해되지 않는지(미끄러운 벽 태그)

## e. 블록아웃 파이프라인
- 내가 maps/ 씬에서 CSG로 블록아웃을 만들고, 에이전트가 그걸 받아 실제 맵으로 만드는 흐름. 이 소단계는 **규칙과 변환 스크립트**를 만드는 것이지 맵을 만드는 게 아니다
- CSG 노드 이름 규칙을 정한다(예: `BLD_` 건물, `DOOR_` 문, `ROOF_` 지붕, `WALL_CLIMB_` 등반 벽, `WALL_SLIP_` 미끄러운 벽, `WATER_`, `TERRAIN_H_` 높이 마커). 이름 규칙 문서를 docs/에 쓴다 — 내가 블록아웃할 때 볼 것
- 변환: CSG → 메시 베이크 + 충돌 생성. 건물은 전부 들어갈 수 있어야 하므로 내부 공간·문이 유지돼야 한다
- 건물 진입: 씬 전환 없이 같은 씬 안에서 **카메라 축소 + ROOF_ 노드 숨김**. 궁전 같은 큰 건물도 별도 씬 없이 실제 크기로
- 검사: 블록아웃 샘플(건물 2채, 문, 지붕, 벽 2종) 하나를 변환해서 들어가고 나오고 지붕이 숨겨지는지

## f. 성능 (간단히)
- 50명 동접 기준: 서버에서 지형 충돌 비용, 클라 드로우콜. 정밀 측정 아니고 "문제 될 수준인가" 판단만
- 검사: 캐릭터 50개를 지형 위에 세우고 서버 틱 시간 보고

## 보고 형식 (소단계마다)
1. 바꾼 파일·함수 목록 (한 줄씩)
2. 슬라이더 목록과 기본값
3. 검사 결과 — 통과/실패와 숫자
4. 결정이 필요한 것
5. 정지. 다음 소단계는 승인 뒤

## 끝나면
내가 시작 마을 블록아웃을 maps/에서 만든다. 그 다음 지시서는 블록아웃을 받아 시작 마을을 실제 맵으로 만드는 것.
